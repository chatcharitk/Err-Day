## Repository layout

The git repository and the actual app live in the **`errday-booking/`** subdirectory, not the
workspace root. Run every command (`npm`, `prisma`, `git`) from inside `errday-booking/`.

## Commands

```bash
npm run dev                              # dev server on :3000
npm run build                            # prisma generate && prisma migrate deploy && next build
npm run lint                             # eslint

npm run db:migrate -- --name some_change # create + apply a dev migration (snake_case name)
npm run db:migrate:deploy                # apply committed migrations
npm run db:migrate:status                # check pending migrations
npm run db:studio                        # Prisma Studio
npm run db:seed                          # seed reference data (prisma/seed.ts)
npx tsx scripts/seed-admin.ts            # create the first admin user
```

There is **no test runner** in this project — no Jest/Vitest/Playwright, no test files. Don't invent
test commands. Verify changes by running `npm run dev` and exercising the relevant flow, plus `npm run lint`.

Note: `npm run build` runs `prisma migrate deploy` against whatever `DIRECT_URL`/`DATABASE_URL` points
at, so a local build needs DB access.

## Architecture

A multi-branch salon booking web app (Thai market, "err.day") on **Next.js 16 / React 19**, Prisma 7 +
Neon Postgres, deployed on Vercel. Thai is the primary language; most user-facing strings live in `*Th`
DB columns.

### Stack specifics that bite

- **Prisma client is generated to `src/generated/prisma/`** (see `prisma/schema.prisma` generator), not
  the default `node_modules/@prisma/client`. Import models/enums from `@/generated/prisma/client`.
  Regenerated by `prisma generate` / any `db:migrate`.
- **DB access goes through the Neon serverless driver.** `src/lib/prisma.ts` wires `PrismaNeon` +
  `ws`. Always import the shared `prisma` singleton from `@/lib/prisma` — never `new PrismaClient()`.
- **Two connection strings:** `DATABASE_URL` (pooled, pgbouncer — runtime) and `DIRECT_URL` (direct —
  Prisma Migrate, see `prisma.config.ts`).
- **Tailwind v4, CSS-first** — config lives in `src/app/globals.css`, there is no `tailwind.config`.
  UI is shadcn/ui (style `base-nova`) in `src/components/ui/`, lucide icons, some `@base-ui/react`.
- **Edge-runtime gate:** `src/proxy.ts` (this Next.js's replacement for `middleware.ts` — exports a
  `proxy` function + `config.matcher`) guards `/admin/*` by **cookie presence only**; real session
  validation happens downstream in server components / route handlers.

### Three auth surfaces (each separate)

- **Customer** — LINE-native via LIFF (`src/components/LiffProvider.tsx`, `src/hooks/useLiff.ts`).
  No password; identified by phone (upserted) and `lineUserId`. Routes: `/book/[branchId]`,
  `/my-bookings`, `/membership/*`, `/liff/*`.
- **Admin** — `/admin/*`. DB-backed sessions (`AdminSession` + httpOnly `admin_session` cookie),
  helpers in `src/lib/admin-auth.ts` (`getCurrentAdmin`, `requireAdmin`, `requireOwner`; roles
  `OWNER`/`ADMIN`). Desktop UI under the `(panel)` route group; a separate mobile UI under `/admin/m/`.
- **Staff** — `/staff/*`. Phone + 4-digit PIN → **HMAC-signed `staff_session` cookie** (no session
  table), `src/lib/staff-auth.ts` (`getCurrentStaff`). Secret = `STAFF_SESSION_SECRET` (falls back to
  `CRON_SECRET`). In-memory PIN rate-limiting.

### Capacity / availability — the core domain (`src/lib/capacity.ts`)

Single source of truth for "can this be booked." Rule: `(# staff on shift covering the window) −
(# overlapping bookings, including unassigned) > 0`. Key behaviors:

- Pure `evaluateCapacity(snapshot, …)` is separated from the DB fetch `loadDaySnapshot(...)`.
- **Online (customer) bookings** enforce a per-branch concurrency cap and require explicit shifts;
  **admin/POS bookings** pass `skipConflictCheck`/`online:false` and bypass the cap (legacy "all active
  staff free" fallback when no shifts exist).
- Cap resolution priority: date-specific `CapacityOverride` > day-of-week override > `Branch.onlineCap`
  > staff-on-shift count. `onlineCap = 0` disables online booking; `null` = no cap.
- `BlockedSlot` (staffId null = whole branch) removes availability.
- **Sale-only SKUs** (membership/package purchases booked through POS) are excluded from capacity —
  they're transactions, not chair time. See `SALE_ONLY_SKUS`.

### Time & money conventions (easy to break — read before touching dates)

- The app serves **Asia/Bangkok (UTC+7)**; the server runs in **UTC**.
- A booking's `date` is stored as **UTC noon of the Bangkok calendar day** (`new Date(date +
  "T12:00:00")`) to dodge the "UTC midnight = previous day in Thailand" bug. Times are local `"HH:mm"`
  strings. Combining them back into a real instant requires the +7h shift (see `bookingMomentUtc` in the
  cron route and the many `Date.now() + 7*60*60*1000` shifts).
- **All money is satang (THB × 100), stored as `Int`.** Divide by 100 only for display. (The expense
  OCR is the one place that works in baht, for the human-review UI.)

### LINE messaging & notifications

- `src/lib/line-messaging.ts` wraps the Messaging API: `pushLine`/`pushText` (counts against quota) and
  `replyLine` (free, ~30s one-shot token). Missing `LINE_CHANNEL_ACCESS_TOKEN` → calls no-op with
  `{ok:false, error:"no_token"}` so dev works without LINE creds.
- **Webhook (`/api/line/webhook`) is intentionally near-silent**: it only auto-replies to tarot-QR
  keywords and a `groupid` helper; all other inbound messages get no AI/auto reply (staff answer
  manually). It also silently captures `lineUserId → displayName`.
- Rich **Flex messages** are built in `src/lib/flex/` (booking, membership, tarot).
- `src/lib/notifications.ts` holds every customer/staff sender. **Idempotency** comes from the
  `NotificationLog` unique `(kind, targetId)` index — re-running a sender is a no-op (P2002 swallowed).
  Owner alerts go to hardcoded `STAFF_LINE_IDS`. Per-branch staff group chats are configured by env
  (`src/lib/line-groups.ts`).

### Cron / scheduled work

`GET|POST /api/cron/notifications` does 4h booking reminders, 1-day membership/package expiry warnings,
and (at 22:00 Bangkok) per-branch next-day summaries + an owner shift DM. Auth: `Authorization: Bearer
$CRON_SECRET`, `?secret=`, or a logged-in admin session. **It is driven by GitHub Actions**
(`.github/workflows/notifications-cron.yml`, every 15 min) — `vercel.json` has no cron block. The 22:00
once-per-day jobs dedupe via synthetic `NotificationLog` targetIds.

### Entitlements: membership vs packages

Two parallel systems, both sellable at POS and both supporting LIFF self-signup that creates a
`pendingActivation` row later finalized at the counter:

- **Membership** (`src/lib/membership.ts`) — 30-day recurring, SKU `svc-membership-30d`. `Membership` +
  one `MembershipCycle` per paid period (renewal history). Unlocks member pricing on services.
- **Packages** (`src/lib/packages.ts`) — `PACKAGE_SPECS`: Buffet 30d (`svc-buffet`, unlimited) and
  5-pack 90d (`svc-pkg5`). `CustomerPackage`; `pickRedemption` redeems the soonest-expiring eligible
  package, `redeemPackage` decrements usage.

POS lives at `/admin/(panel)/pos` → `/api/pos/sale`; selling an entitlement SKU triggers activation.

### Other notable pieces

- **Caching:** `src/lib/branches-cache.ts` wraps slow-changing reference data (branches/services/
  staff/addons) in `unstable_cache` with tags + 5-min revalidate; admin edits invalidate by tag. There's
  also a 30s in-memory admin-session cache per Lambda.
- **Image uploads:** Vercel Blob (`@vercel/blob`, `BLOB_READ_WRITE_TOKEN`) via `/api/upload` +
  `ImageUpload.tsx`. Used for branch/service/staff/customer photos and expense attachments
  (`kind=receipt` also accepts `application/pdf`, unlike the image-only profile/customer-photo kinds).
- **Expenses are manual entry only** — there is no OCR/AI step (removed; the Anthropic SDK is no
  longer a dependency at all). `ExpenseForm.tsx` / `MobileExpenseForm.tsx` support multiple file
  attachments (`ExpenseAttachment`, uploaded independently via `ExpenseAttachments.tsx` as soon as each
  is picked) and a searchable vendor registry (`Vendor` model, `src/lib/vendors.ts`
  `findOrCreateVendorId` — typing any name on save reuses an exact case-insensitive match or creates a
  new Vendor, so the registry builds itself without a separate "add vendor" step;
  `VendorAutocomplete.tsx` is just a reuse-shortcut on top of that, not the source of truth).
- **Payroll → Expense**: two ways to turn payout into a recorded Expense.
  - Daily (`"จ่ายรายวัน"` tab): each row also has an admin-entered `tipSatang` (flat amount, not
    hours×rate) alongside `otHours`. Once a day is marked PAID, "บันทึกเป็นรายจ่าย" opens a review
    panel prefilling commission/OT/tip (editable, not just recomputed) before POSTing to
    `/api/admin/payroll/daily-expense`. Idempotent via `StaffDailyPayout.expenseId` — sconde POST
    a second POST for the same staff/day returns the existing expense.
  - Monthly (`"สรุปรายเดือน"` tab): rolls up each staff's PAID commission+OT for a month
    (`computeBranchMonthlyPayout` in `src/lib/payroll.ts`) and records it as one `commission_bonus`
    Expense per staff. Idempotent via a `[PAYROLL:staffId:YYYY-MM]` marker in `Expense.notes`.
  - Both deliberately exclude base salary/wage — per this file's existing convention, base pay has no
    reliable per-day "worked" signal here — it's disbursed on its own cadence outside the app.
- **Fuzzy customer search:** `Customer` has `pg_trgm` GIN indexes on name/nickname/phone — search uses
  trigram similarity (`/api/admin/search`, `CustomerSearch.tsx`). `Vendor.name` uses the same pattern.
- **PDPA:** Thai data-consent capture (`src/lib/pdpa.ts`, `PdpaConsentBlock.tsx`); consent fields on `Customer`.
- **Branches** are currently `branch-sukhumvit` and `branch-bangna` (referenced by id in
  `line-groups.ts` and seed data).
